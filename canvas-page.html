👨‍💻 Code-Together 9: Iterators & Doubly Linked Lists

🎯 Overview

An in-class code-together activity introducing two new concepts that build on the singly linked list from CT7 and CT8. In Part 1, students add a nested Iterator class to the existing SinglyLinkedList — enabling range-based for loops and standard iterator syntax. In Part 2, students implement a DoublyLinkedList with prev_ and tail_ pointers, unlocking O(1) push and pop from both ends. The scenario follows Farr's Ice Cream: the manager uses an iterator to inspect the ticket queue, then tracks drive-through orders in a doubly linked list.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Explain the purpose of iterators: abstract traversal into a reusable interface that enables range-based for loops
  • Implement a nested Iterator class inside a linked list with operator*, operator++, and operator!=
  • Implement begin() and end() and explain the nullptr sentinel pattern
  • Describe the structural difference between DoublyNode (prev/data/next) and Node (data/next)
  • Implement push_back and pop_back on a doubly linked list in O(1) using tail_ and prev_
  • Explain why doubly linked lists require four pointer updates per insertion/removal

📚 Teaching Order

Work through the files in the order main.cpp calls them:

1. SinglyLinkedList.cpp — Iterator class (5 TODOs) (5 TODOs)

Section What You’ll Learn
operator\* — Dereferencing returns a reference to current_->data; mirrors raw pointer dereference; explain why returning by reference allows *it = value
operator++ — Advancing sets current_ to current_->next and returns *this; pre-increment returns the updated iterator
operator!= — Loop condition compares current_ with other.current_; the range-based for loop calls this before every iteration
begin() — Start sentinel returns Iterator{head_}; if the list is empty, head_ is nullptr and begin() == end()
end() — Past-the-end sentinel returns Iterator{nullptr}; represents one position past the last node

2. DoublyLinkedList.cpp — Doubly linked list operations (10 TODOs) (10 TODOs)

Section What You’ll Learn
push_front — Insert at head four pointer updates: new node links to old head; old head's prev points back; if empty, tail_ is set; head_ advances
push_back — O(1) append four pointer updates: new node's prev links to old tail; old tail's next points forward; if empty, head_ is set; tail_ advances; contrast with CT8's O(n) traversal
pop_front — Remove head save old head; advance head_; clear new head's prev; if now empty, clear tail_; delete saved
pop_back — O(1) removal save old tail; retreat tail_ via prev; clear new tail's next; if now empty, clear head_; delete saved; contrast with CT8's trailing pointer traversal

3. main.cpp — Farr's Ice Cream Scenario (8 TODOs) (8 TODOs)

Section What You’ll Learn
Part 1 — Explicit iterator loop write a for loop using begin()/end()/++/* to print each ticket number
Part 1 — Range-based for write a range-based for loop to count tickets above a threshold; discuss how the compiler rewrites it into the explicit form
Part 2 — push_back (×4) cars join the drive-through lane; demonstrates O(1) append with tail_
Part 2 — push_front VIP car added to the front
Part 2 — pop_front front car is served
Part 2 — pop_back last car gives up; O(1) vs CT8's O(n) trailing pointer

🔧 Troubleshooting

CMake does not configure automatically

  1. Make sure you have Desktop development with C++ workload installed in Visual Studio
  2. Go to Project → CMake Settings and ensure the configuration is correct
  3. Try Project → Delete Cache and Reconfigure
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In Visual Studio, select ct9-iterators-doubly-linked-lists.exe as the startup item from the dropdown
  2. Press Ctrl+F5 to run without debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
